# Docker イメージの基本操作：まずはイメージを確認する

[English](../docker-image-basics.md) | [中文](../zh/docker-image-basics.md) | **日本語**

今日から Docker イメージの学習を始めた。まだ扱った内容は多くなく、主にローカルのイメージの一覧表示、イメージの詳細情報の確認、不要になったイメージの削除である。

このノートでは、現時点で実際に理解できた部分だけを記録しておく。イメージのレイヤー、プル、タグ、ビルドを学んだら、引き続き追記していく。

## 1. ローカルのイメージを一覧表示する

```bash
docker image ls
```

このコマンドは、Docker Engine が現在保持しているイメージを一覧表示する。よく使われる省略形もある。

```bash
docker images
```

出力はおおよそ次のようになる。

```text
REPOSITORY   TAG       IMAGE ID       CREATED       SIZE
alpine       latest    294b683cb724   5 weeks ago   14.6MB
```

各フィールドの意味は次のとおり。

- `REPOSITORY`：イメージが属するリポジトリ名。たとえば `alpine`。
- `TAG`：イメージのタグ。たとえば `latest`。
- `IMAGE ID`：ローカルのイメージの識別子。デフォルトでは先頭部分だけが表示される。
- `CREATED`：イメージが作成された日時であり、私がダウンロードした日時ではない。
- `SIZE`：現在の Docker 環境で表示されるイメージのサイズ。

イメージは通常、「リポジトリ名:タグ」の形で参照できる。

```text
alpine:latest
nginx:alpine
```

タグを省略すると、Docker は通常 `latest` を使う。ただし `latest` はただのタグ名にすぎず、Docker がどのバージョンが最新かを自動的に判断するという意味ではない。

完全な ID を確認したい場合は、次のようにする。

```bash
docker image ls --no-trunc
```

特定のイメージだけを探したい場合は、名前を直接指定できる。

```bash
docker image ls alpine
```

ここで得られるのは Docker Engine のローカルにすでにあるイメージであり、リモートのレジストリの検索結果ではない。

## 2. イメージの詳細情報を確認する

```bash
docker image inspect alpine
```

`inspect` は JSON を返す。`image ls` の要約と比べると、Docker が実際に保持しているイメージのメタデータにずっと近い。

イメージは、タグ付きの名前やイメージ ID で確認することもできる。

```bash
docker image inspect alpine:latest
docker image inspect 294b683cb724
```

このコマンドは一度に複数のイメージを確認できるため、出力の最も外側は配列になっている。

```bash
docker image inspect alpine nginx:alpine
```

### 現在注目しているフィールド

| フィールド | 私の理解 |
|---|---|
| `Id` | ローカルのイメージの設定オブジェクトを表す、内容に基づく完全な識別子 |
| `RepoTags` | このイメージを指しているリポジトリ名とタグ |
| `RepoDigests` | レジストリから取得したイメージに対応する、内容ダイジェストによる参照 |
| `Created` | イメージのメタデータに記録された作成日時 |
| `Os` | イメージが対象とする OS。たとえば `linux` |
| `Architecture` | イメージが対象とする CPU アーキテクチャ。たとえば `arm64` |
| `Size` | イメージのサイズ。JSON では通常バイト単位で表される |
| `Config` | イメージがコンテナのために用意しているデフォルトの実行設定 |
| `RootFS.Layers` | イメージのルートファイルシステムを構成するレイヤーのダイジェスト |

`Config` の中では、さらに次のような重要な情報を確認できる。

- `Env`：イメージにあらかじめ設定された環境変数。
- `Cmd`：コマンドを別途指定しなかった場合に使われるデフォルトのコマンド。
- `Entrypoint`：イメージに設定されたエントリーポイントのプログラム。
- `WorkingDir`：コンテナ起動後のデフォルトの作業ディレクトリ。
- `User`：イメージがデフォルトで使うユーザー。
- `ExposedPorts`：イメージが宣言しているサービスのポート。

すべてのイメージがこれらのフィールドをすべて設定しているわけではない。設定されていないフィールドは空であったり、出力に現れなかったりする。

`ExposedPorts` はイメージが提供する情報にすぎず、ポートを自動的にホスト環境へ公開するわけではない。実際にポートマッピングを行うには、コンテナを実行するときに `-p` などの設定が必要である。

ここであらためて確認できたことがある。イメージはファイルの集まりだけではなく、コンテナを作成するときに使われるデフォルトの設定も持っている。`docker run` でコンテナを起動するとき、イメージのファイルシステムの内容とこれらの設定の両方が使われ、コマンドラインの引数でその一部のデフォルト値を上書きできる。

## 3. `inspect -f` で必要な情報を取り出す

完全な JSON は詳細だが、1 つのフィールドだけを見たいこともある。そのときは `--format` の短縮形である `-f` を使う。

```bash
docker image inspect -f '{{.Id}}' alpine
```

`-f` の後に書くのは Go のテンプレートである。最も基本的な書き方では、`.` で表される現在のオブジェクトから始めて、JSON のフィールド階層をたどっていく。

たとえば、OS と CPU アーキテクチャを確認する。

```bash
docker image inspect -f '{{.Os}}/{{.Architecture}}' alpine
```

出力は次のようになる。

```text
linux/arm64
```

デフォルトのコマンドを確認する。

```bash
docker image inspect -f '{{json .Config.Cmd}}' alpine
```

デフォルトの作業ディレクトリを確認する。

```bash
docker image inspect -f '{{.Config.WorkingDir}}' alpine
```

イメージのタグの一覧を確認する。

```bash
docker image inspect -f '{{json .RepoTags}}' alpine
```

ここで `json` を使っているのは、配列や入れ子のオブジェクトを、テンプレートのデフォルトの表示形式に頼らず、正しい JSON として出力させるためである。

したがって、現時点での `inspect -f` の理解は次のとおりである。

```text
inspect       オブジェクトの完全な情報を取得する
    ↓
--format      テンプレートで出力を選択・整形する
    ↓
{{.Config.Cmd}}  フィールドの階層をたどって値を取り出す
```

フィールドのパスがわからないときは、まず完全な `inspect` の JSON を一度確認し、その入れ子の構造に合わせてテンプレートを書けばよい。

## 4. ローカルのイメージを削除する

```bash
docker image rm alpine:latest
```

同等の書き方が 2 つある。

```bash
docker image remove alpine:latest
docker rmi alpine:latest
```

削除コマンドには、イメージ名、タグ付きの名前、イメージ ID のいずれも指定でき、複数の対象を一度に指定することもできる。

```bash
docker image rm alpine:latest nginx:alpine
```

ここで削除されるのは、現在の Docker Engine にあるローカルのイメージやタグであり、リモートのレジストリの内容は削除されない。

タグとイメージそのものも区別する必要がある。同じイメージを参照している別のタグがまだあれば、1 つのタグを削除しても、その名前による参照が外れるだけで、下層のイメージデータがすぐに消えるとは限らない。

あるコンテナがまだそのイメージに依存している場合、Docker は削除を拒否して競合を報告することがある。その場合は、エラーを見てすぐに強制削除するのではなく、まず関連するコンテナがまだ必要かどうかを確認すべきである。

```bash
docker ps -a
```

`docker image rm` には `-f`（`--force`）もあるが、それは参照関係を理解したうえでの意図的な選択であるべきで、デフォルトの操作にすべきではない。

## 5. 今日得られた基本的な理解

現時点では、イメージを次の 2 つの部分として捉えている。

```text
Docker Image
    ├── ファイルシステムの内容
    └── コンテナ作成に必要なデフォルトの設定
```

今日使ったコマンドと対応づけると、次のようになる。

```text
docker image ls       ローカルにどのイメージがあるかを確認する
docker image inspect  イメージに何が記録されているかを確認する
inspect -f            詳細情報から必要なフィールドを取り出す
docker image rm       ローカルのイメージやタグを削除する
```

これはイメージの学習の入り口にすぎない。イメージがなぜレイヤーに分かれているのか、タグとダイジェストはどう違うのか、プル時に実際に何がダウンロードされるのか、Dockerfile がどのようにイメージを生成するのかは、今後学んでから追記していく。
